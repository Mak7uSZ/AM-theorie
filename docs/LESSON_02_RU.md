# Урок 2: ваша теория, четыре иллюстрации и три сцены

Подготовлена следующая небольшая версия Voorrang. Это начало наполнения темы, а не завершённый Milestone 2: пока 3 сцены из будущих 10, без постоянного сохранения и разблокировки других тем.

## 1. Обновите три существующих объекта

Нажмите **Stop** перед изменениями. Для каждого объекта откройте соответствующий файл в редакторе, скопируйте **полное содержимое** и замените старый код в Studio:

| Explorer: объект | Тип | Полный файл на диске |
| --- | --- | --- |
| ReplicatedStorage → TopicContent | ModuleScript | src/ReplicatedStorage/TopicContent.lua |
| ServerScriptService → Boot | Script | src/ServerScriptService/Boot.server.lua |
| StarterPlayer → StarterPlayerScripts → ClientController | LocalScript | src/StarterPlayerScripts/ClientController.client.lua |

Новых скриптов и ручных 3D-объектов создавать не нужно. Все три файла нужно обновить вместе: формат страниц теперь содержит заголовок, текст, ключ картинки и подпись.

Что делает каждый компонент:

- **TopicContent**: шесть страниц согласованной нидерландской редакции, источники, статус `awaiting_review`, четыре ссылки на изображения. Здесь нет ключей ответов.
- **Boot**: три определения сцен и правильные ответы только на сервере; создание перекрёстка и движущегося велосипедиста/автомобиля/трамвая; следующий вопрос, повтор попытки, результат и очистка площадки.
- **ClientController**: книга с текстом и изображением, камера, кнопки ответа, «следующая сцена», «повторить», «вернуться».

Первые шесть страниц:

1. Bestuurders en weggebruikers.
2. Lopen of fietsen?
3. Een gelijkwaardig kruispunt herkennen.
4. Bestuurders van rechts.
5. Uitzondering: onverharde weg.
6. Uitzondering: tram.

Текст уже включён, но в заголовке виден `CONCEPT — actualiteitscontrole open`: мы не выдаём незавершённую сверку текущей редакции RVV за окончательную.

## 2. Импортируйте четыре картинки

PNG в репозитории не превращается в Roblox-изображение автоматически: Roblox назначает загруженному ресурсу свой ID.

1. Откройте **Window → Asset Manager** (в некоторых раскладках доступен через Home).
2. Выберите **My Inventory**, либо **Project** вашей игры. Загружайте от имени того же владельца, которому принадлежит experience; если игра групповая, выбирайте соответствующую группу.
3. Нажмите **Import**. Выберите четыре PNG из папки `assets/theory/voorrang`: `bestuurders.png`, `rechts.png`, `onverhard.png`, `tram.png`. Если окно предлагает параметры импорта, выберите тип изображения; проверьте владельца перед загрузкой.
4. Дождитесь завершения загрузки. После импорта найдите каждое изображение, откройте контекстное меню и используйте **Copy Asset ID**. Если интерфейс предлагает несколько типов ресурсов, нужен ID изображения, подходящий для `ImageLabel.Image`, а не ID модели/place.
5. В `ReplicatedStorage/TopicContent` найдите таблицу `images` в начале файла. Вставьте реальные ID между кавычками. Например, поле `rechts = ""` должно стать `rechts = "ВАШ_ЧИСЛОВОЙ_ID"`; слова `ВАШ_ЧИСЛОВОЙ_ID` вводить не нужно. Код принимает также полный вид `rbxassetid://...`.
6. Скопируйте тот же полный `TopicContent` обратно в файл репозитория, чтобы ID сохранились для второго ПК. Нажмите F5 и откройте книгу.

Пока ID пусты, книга показывает понятное сообщение `Illustratie nog niet gekoppeld`, и текст остаётся доступен. ID здесь не выдуманы и автоматически не загружены.

Если картинка не появляется: проверьте ID и владельца/разрешения ресурса. Новый ресурс может ещё обрабатываться или проверяться Roblox. Через 8 секунд клиент пишет предупреждение в Output, если изображение так и не загрузилось. Отсутствие картинки не блокирует остальные страницы.

Официальные инструкции: [Asset Manager](https://create.roblox.com/docs/projects/assets/manager), [импорт изображений и asset ID](https://create.roblox.com/docs/parts/textures-decals), [ImageLabel](https://create.roblox.com/docs/reference/engine/classes/ImageLabel).

## 3. Пройдите три сцены

1. **Spelen → синий круг 5 секунд → все 6 страниц → Theorie afronden.**
2. **Оранжевый круг 5 секунд.** Первая катсцена: велосипедист движется справа к перекрёстку. После 4 секунд камера останавливается для вопроса.
3. Ответьте и прочитайте объяснение. Затем **Start de actie**: коротко держите W или Vooruit и отпустите, чтобы остановить блок в жёлтом учебном секторе на секунду.
4. Результат разделяет **Kennis** и **Stopactie**. **Opnieuw** повторяет текущую сцену, **Volgende scène** запускает следующую.
5. Вторая сцена: вы подъезжаете по грунтовой дороге, автомобиль слева — по асфальтированной. Третья: трамвай слева на нерегулируемом перекрёстке.
6. После третьей сцены доступен возврат в лобби или повтор. Итоги показывают отдельное количество верных ответов и остановок. Повтор заменяет результат соответствующей сцены, не добавляет лишние баллы. Выход в лобби завершает эту тренировочную серию; следующий заход начинает её заново.

Жёлтый сектор — искусственная цель упражнения, **не дорожный знак обязательной остановки**. Остановка на каждом перекрёстке не преподаётся как правовая обязанность. Пока проверяется только аккуратная остановка перед пересечением, а не весь процесс уступания, ожидания и последующего проезда. Скорость задана в studs/s, не км/ч.

## 4. Быстрая проверка

- [ ] Книга содержит ваш текст, 6 страниц и пометку незавершённой проверки.
- [ ] При заполненных ID показываются нужные изображения и подписи. При пустых ID нет красной ошибки.
- [ ] В первой сцене велосипедист справа, во второй автомобиль слева и грунт под вашим блоком, в третьей — трамвай слева.
- [ ] Вопросы и объяснения различаются; правильный ответ не раскрывается до выбора.
- [ ] «Следующая сцена» появляется после действия; третья сцена не уходит в несуществующую четвёртую.
- [ ] Неправильный ответ и успешная остановка показывают разные оценки.
- [ ] Повтор не увеличивает итог сверх числа пройденных сцен.
- [ ] Возврат/смерть восстанавливает обычную камеру и ходьбу; второй игрок не теряет свою площадку.

В Output включите Server и Client, фильтр `[AM Theory]`. Сервер теперь выводит `question=cyclist_right_01`, `question=unpaved_01`, `question=tram_demo_01`, номер страницы, выбранный ответ, итог остановки и переходы.

## Проверено вне Studio

Все три исходника компилируются Luau. Автоматический тест выполняет настоящий исходник Boot на подменённых объектах движка: 54 проверки таймеров, книги, трёх ответов, повторов, устаревших токенов, раздельных результатов, двух игроков и очистки сцен. Это не эмуляция рендера или физики Roblox.

Для технического повторения теста при наличии официального Luau CLI:

```powershell
.\tests\run-server-tests.ps1 -LuauPath "ПУТЬ\К\luau.exe"
```

Эта версия ещё не запускалась в Roblox Studio. После обновления пришлите первую красную ошибку Output, если она появится, либо снимок страницы книги и сцены для оценки расположения элементов.
